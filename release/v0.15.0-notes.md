## XIUI PartyCare Fusion v0.15.0

### Dilation Ring-aware Refresh and Haste cues

This release corrects the early Refresh and Haste cue timing when the local caster has HorizonXI’s **Dilation Ring** equipped. At the start of a confirmed local Refresh or Haste cast, PartyCare now checks the equipped gear and records the ring’s documented **+30-second ally duration** for that specific visual timer.[^1]

With the default 15-second lead, a Dilation Ring-enhanced Refresh now begins its purple pulse at the actual final 15 seconds rather than 30 seconds early. Haste receives the same correction. The base-duration sliders remain available for the normal spell durations, and a new **Auto-adjust for equipped Dilation Ring (+30s)** checkbox appears under `/xiui → Party List → Refresh and Haste Name Cues`. It is enabled by default and can be disabled for an unusual setup.

The XIUI party-status data confirms whether Refresh/Haste is active but does not provide remaining seconds. Therefore, PartyCare intentionally starts an exact early countdown only from a locally observed cast; it does not invent an expiry timer for a buff applied by another player or present before XIUI loads. The active status icon still remains authoritative for missing-buff cues.

All XIUI Lua files and the full deterministic test suite passed. New regressions verify the extended timing for both Refresh and Haste, plus the checkbox opt-out. A clean archive extraction also passed Lua syntax validation.
