## XIUI PartyCare Fusion v0.15.1

### Reliable Dilation Ring +30-second timing

This targeted follow-up addresses a live report where the **Auto-adjust for equipped Dilation Ring (+30s)** option was enabled but a client did not expose the equipped ring through the first Ashita inventory read.

PartyCare now checks the local equipment at **both** Refresh/Haste cast start and cast completion, retains the greater valid modifier, and normalizes the item name before comparison. This covers delayed equipment-memory updates without changing cast behavior.

A new fallback is available under `/xiui → Party List → Refresh and Haste Name Cues`:

> **Always apply Dilation Ring +30s to local casts**

Enable that fallback only while Dilation Ring is equipped for the cast. It applies the documented 30-second duration bonus to every locally observed Refresh and Haste without relying on inventory detection.[^1] It remains fully manual: it changes only the visual early-warning timer and never casts, targets, retries, or changes any spell action.

The existing **Auto-adjust for equipped Dilation Ring (+30s)** control remains enabled by default and is still the preferred setting. The fallback exists specifically for a client, hook, or gear processor that does not provide the equipment state reliably enough at action time.

All XIUI Lua sources and the complete deterministic regression suite passed. New test coverage verifies delayed equipment visibility at cast completion and the explicit fallback, in addition to the original automatic Refresh/Haste extension tests. A clean archive extraction also passed Lua syntax validation.
